# 事業者カードから1社を選ぶ予約

## 変更後の流れ

フォームの条件入力 → 事業者ごとのカードを自動表示 → 「この事業者に予約を依頼する」。候補検索に連絡先の入力や規約同意は不要。入力が650ミリ秒止まり、移動・ペットの条件と経路計算が揃うと検索する。自動表示でフォーカスやスクロールは動かさない。候補検索では予約シートへの保存やメール送信をしない。連絡先も候補検索には送らない。

カードは「提携先」シートの受付状況、対応エリア、車の定員、ペット数、大型犬、荷物、ケージ貸出、介助、営業時間と受付期限を現在の判定ルールで絞る。対応エリアが「全国」の事業者も含める。空き状況は引き受け時の確認になる。

料金は `tools/fares.json` から生成したデータを予約処理でも使う。`partner_id` を提携先シートのIDに対応させる。現在の登録は P002 と P003。料金表のない会社は「料金はお見積もり」と表示し、他社の料金で代用しない。会社名は候補カードで表示する（2026-10-30 ユーザー確認済み）。

候補は15分間有効。依頼時には署名、入力条件、料金表、受付状況を再検証する。送信を繰り返す場合も同じ受付番号を返す。選択した会社のIDを予約シートに保存し、その会社以外への通知・追加の一斉送信・引き受けを止める。旧画面からの事業者未指定の新規依頼は受け付けない。変更前に受け付けた予約は既存の流れを維持する。

## 本番反映

**Apps Script への貼り直しが必要です。** GitHubへのマージだけでは予約処理は更新されない。

1. PRの内容をオーナーが確認する。本番のApps Scriptコードを控え、リポジトリとの差分と設定・追加関数を確認する。秘密情報は公開リポジトリに入れない。
2. 予約シートの「設定」B1 が「止める」であることを確認して維持する。送信再開は別の明示指示が必要。
3. `booking/Code.gs` の変更を本番プロジェクトへ反映し、既存のウェブアプリのURLを変えずに新しいバージョンへ更新する。貼り直すのは生成済みのCode.gs 1ファイル。
4. 同じ作業時間内にPRをマージして画面を更新する。先に画面だけ公開しない。移行中の旧画面は依頼を受け付けない時間があるため、短時間で揃える。
5. 公開画面で候補検索を確認する。実際の予約・通知テストは送信先を確認したうえで別途実行する。

料金は目安であり、実際の空き状況・確定運賃を保証しない。経路・迎車距離は既存と同じ推定を使う。料金表が未登録の会社にも数値を表示したい場合は、その会社の料金表を確認して元データへ追加する。

## 比較カードと地図

地図の欄は地図だけを表示する。事業者カードは連絡先の入力欄より前に置く。一般道・高速利用時の運賃目安と、乗車運賃・迎車・回送・夜間早朝割増・待機・端数調整を表示する。高速道路の通行料は未取得のため実費として分け、運賃目安を通行料込みの総額と見せない。高速経路が取得できない場合は数値を捏造せず要見積もりとする。

迎車・回送の公開情報が足りない場合は、非公開の単価は仮置きせず、公開された基本額だけを含め、追加分は要見積もりとする。別記のない迎車・回送を無料と断定しない。カードの近くで、価格差は各社の運賃体系と営業所からの距離等によることを説明する。
