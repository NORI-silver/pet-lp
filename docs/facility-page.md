# 施設ページの型（1施設1ページ）

[B] 集客（SEO・AI検索）。2026-11-08 戦略担当の「月間100万PV」の道すじ（打ち手3）で、施設1つずつのページを作る前に、全カテゴリ（病院・火葬／霊園・シッター・トレーナー・ホテル・老犬ホーム・ドッグラン・トリミング・ペットタクシー会社）で同じ型にそろえるために決めた。新しいカテゴリの施設ページもこの型で作る。

## ねらい

- 検索：「施設名」「施設名 料金」「施設名 行き方」で来る人に、公式サイトより早く要点が分かるページ。
- AI検索：ChatGPT・Perplexity・AIによる概要が、答えの出どころとして名前とリンクを出しやすいページ（短い言い切りの文・数字・出どころ・確認日）。
- AIの要約でクリックが減る分は、「開かないと用が足りないもの」で補う：同じ県・同じ条件のほかの施設とのくらべ、地図、口コミ本文、ここまでのペットタクシーの料金。

## 作るか・作らないか（薄いページを出さない）

- 公式サイトで確かめた項目（下の「事実の表」）が **5つ以上** ある施設だけページを作る。足りない施設は一覧のカードのまま（ページを作らない。noindex で量産もしない）。
- 1回に作るのは1カテゴリずつ。生成のあと `tools/seo_check.py` と、10ページを人の目で（AIが）読んで確かめてから公開する（AGENTS.md「大量生成・品質確認なしの公開はしない」）。
- 閉店・移転が分かったら、ページを消さずに「閉じた・移った」と書いて一覧からは外す（URLは残す）。

## URL・title・h1

- URL：`/<カテゴリ>/<県slug>/<施設id>/`（例 `/sougi/tokyo/s0123/`）。id はデータの `id`（変えない）。名前を URL に入れない（改名で URL が変わるため）。
- title：`施設名（市区町村）｜料金・受付時間・行き方｜ペットタクシー予約窓口`（項目はそのページにあるものだけ）。
- h1：施設名だけ。
- description：答えの1文（下の「要点」の1行目）をそのまま。

## ページの並び（上から）

1. **要点**（答えを先に。3〜5行の箇条書き）：何の施設か・どこか・いつ開いているか・いくらか・ほかとちがう点。数字は公式サイトのとおり。「おすすめ」「人気」「No.1」は書かない。
2. **事実の表**（`<table>`）：項目・内容・出どころ。出どころの列は「公式サイト（◯年◯月◯日に確認）」でリンク付き。書いていない項目は行ごと出さない（「不明」と書かない）。
3. **この施設までのペットタクシー**：所在地があれば `/?to=<所在地>#form` へのボタン（病院の一覧と同じ文「この施設までのペットタクシーの料金をくらべる →」）。往診・訪問の施設（シッター・出張トリミング・往診）は付けない。
4. **同じ県の同じ種類の施設とくらべる**：同じ県の施設を3〜10件、同じ列（料金・時間など）で並べた表。順位は付けない（並びは市区町村の五十音か、データの順）。
5. **口コミ**：星と本文はいまの一覧と同じしくみで毎回取り寄せる（保存しない・構造化データに入れない）。
6. **よくある質問**：その施設の事実の表から作れる質問だけ（2〜4問）。答えは表と同じ数字。
7. **関連する記事**：カテゴリのえらび方の記事、県のページ、緊急・夜間の一覧。

## 構造化データ（JSON-LD）

- `BreadcrumbList`：トップ › カテゴリ › 県 › 施設。
- 施設は schema.org の型を1つ：病院 `VeterinaryCare`、火葬・霊園 `LocalBusiness`（`additionalType` に「ペット霊園」など日本語）、シッター・トレーナー・ホテル・老犬ホーム・トリミング `LocalBusiness`、ドッグラン `Place`（公営は `Park`）。
  - 入れる：`name`・`url`（公式サイト）・`address`（`PostalAddress`、都道府県・市区町村・番地のうち確かめたもの）・`openingHours`（公式の時間が決まった形で書けるときだけ）・`priceRange`（公式の料金が書いてあるときだけ、そのままの円）・`areaServed`（訪問型）。
  - 入れない：`telephone`（電話番号は出さない）・`aggregateRating`・`review`（口コミは保存しないため。自分で集めた評価でもない）・`geo`（約1kmにまるめた位置しかない施設は入れない）。
- ページ自体は `WebPage` に `dateModified`（事実の表の確認日のいちばん新しい日）と `isBasedOn`（公式サイトのURL）。sitemap の lastmod は `tools/lastmod.json` のしくみがそのまま使える（`<main>` の中が変わった日）。

## 文の書き方（AIに引用されやすく）

- 1文に1つの事実。主語に施設名を入れる（「◯◯は、21時から翌朝5時まで受け付けています（公式サイト、2026年11月8日に確認）」）。「こちら」「当院」のような、ページの外で意味が通らない言い方はしない。
- 数字は単位つき・税込か税抜かも書く。幅は「◯円〜◯円」。
- 予想や評価は書かない（「便利です」「安心です」は書かない）。
- 電話番号・個人名（院長名など）・運営会社の代表者名は書かない。

## データ

- 施設の事実は、各カテゴリのデータ（`tools/*.json`）に `facts: [{k, v, src, checked}]` の形で持つ（pet-db の出どころのルールと同じ。`src` はURL、`checked` は確認日）。表もJSON-LDも要点もここからだけ作る（AIに毎回書かせない）。
- `tools/site_watch.py` の照合の対象に施設ページの `src` も入れ、公式サイトから文が消えたら Issue に出す。

## llms.txt・WebMCP

- `llms.txt` には施設ページを1つずつは並べない（多すぎるため）。カテゴリと県のページを並べ、「施設ごとのページは /<カテゴリ>/<県>/<id>/」と形だけ書く。
- `webmcp/data.json` の行に施設ページのURL（`page`）を足す。
