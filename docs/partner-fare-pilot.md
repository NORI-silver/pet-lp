# 提携確認の料金検算（試行）

既存の二段階の申し込みと提携確認ページを使う。公開の料金は出どころ付きで訂正可。運営では税込の会社回答を同じ候補料金エンジンの結果と、画面表示用の丸め前と、飼い主さんに表示される額の両方で比べる。両方の差が300円以内なら、その例だけ一致。空欄、記載のない項目、計算できない条件は0円と区別する。既存・新規申し込みは試行を無効にしても利用できる。

## 運営者が試行する前に

1. 専用の回答ブックを作り、予約ブックと別であること、リンク共有なし・閲覧と編集は必要な運営者だけであることを個別に確認する。回答や内訳は、公開リポジトリ、料金表示、URL、メール、一般の予約ブックに載せない。
2. 受付とサイトの `/go/` を同じ試行で確認する。受付を先に反映したテスト環境で、POSTを返すこと、一般の申し込みと提携確認、失敗時、再送時を確認する。オプトイン `PCONF_FARE_PILOT=on` と `PCONF_PRIVATE_FILE_ID` は専用ブックの確認後だけ、非公開の設定に入れる。既定は無効。
3. 相手本人・担当窓口と試行の了承を確認してから、運営側で `makePconfFareLink_(id)` を呼ぶ。通常の見本リンク・公開サイトURLだけでは試行を開けない。有効期限7日、回答は1リンク1件。再回答が必要なら新しい専用リンクを発行する。リンクは公開せず、料金や回答は変更しない。
4. 例が一致しても自動登録しない。営業所起点や指定ルートの実例、税込の独立見積もりと算定の根拠、丸め、境目、往復、待機、深夜と実費のうち該当項目がそろってから、本人確認済みの回答を運営がレビューする。公開回答の訂正は未評価として残す。依頼・連絡の自動送信はしない。

最初の試行はおさんぽの公開表を基に、一般道・片道・朝・待機なし、同じ実車距離と異なる迎車距離の例だけ。現在は迎車距離の20kmが「超えた後」の型と定額・超過距離単価・加算なしに対応。別の境目・端数・計測方法・条件は運営確認。実経路や往復などの精度、実予約での価格差の原因、全社の規則は検証済みではない。
