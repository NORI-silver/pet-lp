# 共通ルール：ユーザーの条件で、選べるマッチングをつくる

対象：ペット・KATACHI・アグリ。調査、データ、画面、集客、提携、点検の全担当・全AIに適用する。既存サービスを探しやすくする場合も、今まで成立しづらかった依頼を成立させる場合も同じ。

## 集めるのは「自分の場合でも大丈夫？」に答えるデータ

「綿の男性用Tシャツ・S」「ドッグランあり」「ペット受入可」のような分類は入口にすぎない。**実際に使う場面で、何が分かれば選べるか。この答え次第で候補が変わるか**を先に考える。利用者が条件をうまく言葉にできないときも、検索語、相談、口コミ、選ばれなかった理由、利用後の体験から、次に見落としそうな問いを見つける。珍しくても安全や利用可否を左右する条件は落とさない。逆に、判断を変えない項目や質問は増やさない。

| 分野 | 表面的な項目で終わらせない例（実在先の情報ではない） |
| --- | --- |
| ペット・宿泊 | ランの最低柵高（cm）・隙間・地面と扉、貸切か共有か。部屋ごとのベッド間の実測幅、荷物を広げたときの床と通路。柵高だけで飛び越えないと断定しない。 |
| ペット・避難 | 施設・災害種別・開設状況を分け、動物の種類や体格・頭数・ケージ条件、屋内外と受入場所、人と一緒に避難できるか／同室で過ごせるかを別々に確認する。過去の運用は今回の開設・受入保証にしない。 |
| KATACHI・ものづくり | Tシャツなら混率とサイズに加え、触感（なめらかさ・毛羽立ち等の比較）、照明ごとの見え方、保温・発熱の試験方法と条件。着用者の感想と試験値、原布の性能と完成品の性能は別。工場はその素材・寸法・公差・数量・図面の有無の組合せで受けられるかを、拠点と案件条件付きで見る。 |
| アグリ・農産物 | 品目だけでなく、熟度・食感・ばらつき、サイズ範囲、週ごとの小口数量、納品場所・時間帯、欠品時の代替と冷蔵便。農家の登録や過去の出荷は、今の在庫・受注可否ではない。 |
| アグリ・農機修理 | 機種だけでなく、型番・症状、他店購入・旧型の受付、出張範囲と条件、持込や引取の可否、部品の調達可否。同じメーカーの取扱い・所在地だけで出張や対応を確約しない。 |

## 集め方と残し方

1. 分野ごとに「利用シーン・問い ↔ 利用者側の必須条件／好み ↔ 供給側の値・範囲 ↔ 確認方法 ↔ 表示・判定 ↔ 再確認条件」を、既存の正本・項目表にひもづける。値ごとに単位、対象（部屋・区画・型番・拠点など）、適用条件、出典、観測・確認日を残す。数値と体験談を同じ欄に混ぜない。項目や事業者が見つからなかった場合も、探索範囲と不足を記録し、次に埋める。
2. 口コミは、公式説明から抜けた選択条件と実際の使い勝手を見つける一次の手がかり。いつ・どの部屋や商品・誰のどんな条件かを添え、複数の異なる体験や写真、公式資料・実測も突き合わせる。単一の口コミを現行ルールや保証にしない。相反する情報は消さず、理由と未解決点を記録する。捏造・無断転載・個人の特定はしない。
3. 通常公開されているページ、仕様書・説明書・自治体資料、普通の検索や閲覧、アクセスが認められた既存記録から、取れる事実は自律的に調べて内部整理する。転載の可否が不明なだけで、閲覧・事実の整理まで一律に止めない。**閲覧・取得、内部保存、外部転載・公開、外部連絡は別の判断**。明確に禁止されている方法やアクセス制限の回避はしない。判断が割れる場合は、その方法・素材・公開部分だけを切り分け、通常の閲覧、事実の要約と出典、利用できる別資料で前進する。原文・画像・私信・個人情報は、利用条件と必要な許可が確認できる範囲だけを扱う。
4. 先に通常の公開情報・既存回答・事業者がすでに入力できる項目で埋める。それでも可否や候補を変える点に限り、外部連絡が許可されている範囲で、答えやすい一問にまとめる。重複・大量・一律の連絡はしない。ペット事業者への送信停止を含め、事業ごとの公開・連絡・承認ルールは変更しない。

## マッチングにどう使うか

- 必須条件は候補の可否に、好みは比較と並び順に使う。条件は単独でなく組合せで見る。**適合／条件付き／非適合／未確認**を混ぜない。必須条件の未確認、期限切れ、矛盾は確認済みの適合に数えず、根拠のある非適合とも区別する。
- 結果では「あなたのこの条件に合う／合わない理由」「どの条件なら使えるか」「決めるために未確認の一点」を短く出す。判断に関係しない欠落を一面に並べたり、全部を最初に入力させたりしない。0件でも無断で必須条件をゆるめず、同意を得て候補が変わる条件を示す。
- 更新時は、古い値、情報の矛盾、未回答で多い問いを担当と再確認条件付きで追い、正本と表示をそろえる。実績のない推定をサイトや営業説明に流さない。

## 全担当が出すもの

- **要**：事業ごとの優先する利用シーンと担当を決め、各視点の反論をそろえて判断する。**策**：その情報で既存の探し方より何が良くなるか、供給範囲を狭めずどの穴から埋めるかを決める。**算**：成立・売上・利益に効くか、収集や先方の負担に見合うかを測る。
- **問**：まだ聞けていない質問と、答えで候補が変わる反例を出す。**種**：仮説を出典付きの比較可能なデータにする。**結**：既存の回答と対象範囲をつなぎ、協力先の負担を減らす。**文**：必要なら許可範囲で、既知のことを繰り返さない質問にする。
- **形**：必須・好みと結果の理由を、少ない操作で伝える。**道**：実際に検索される問いに、一般論でなく判断材料で答える。**縁**：案内や紹介先に誤った期待を持たせず、ミスマッチだった例を次の改善に返す。**灯**：期限・矛盾・頻出する不足を見つけて担当に返す。
- **鏡**：作り手と独立に、普通の例・合うが珍しい例・合わない例・未確認／矛盾の例を点検する。**関**：根拠、適合判定、公開範囲の違反を止め、サイトとAPIなど同じ条件の入口で結果がぶれないかを確認する。

## 精度を上げたと言える条件

同じ実利用に近い匿名化・合成の評価ケースで、従来の項目だけの場合と比べる。**正しく適合・非適合を判断できた率、誤って適合とした率、判断できずに残った率、判断までの時間、追加確認の回数**を、0件・未確認も含む同じ分母で確かめる。可能なら実案件で利用・納品・修理までの完了も追う。合成ケースは実績に含めない。対象・情報・検証ケースの件数だけ増えても、精度が上がったとは言わない。
